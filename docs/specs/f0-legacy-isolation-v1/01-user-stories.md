# Round 1 — F0 用户故事与验收边界

## US-F0-01：正常用户不触达遗留运行时

作为正常 QM 用户，我继续使用已批准的现有 harness 完成 turn；即使旧配置或请求携带遗留 harness ID，也不会触发遗留进程、沙箱、网络或自动导入。

验收：F0-01、F0-02、F0-06。

## US-F0-02：运营人员不看到虚假的控制能力

作为运营人员，我不能从 core API 或管理插件访问未实现真实动作证明的 Agent Registry、消息、调度、应急和 dashboard 路径；它们是未路由，而非返回成功。

验收：F0-03、F0-04。

## US-F0-03：管理员身份不会降级

作为管理员，我必须通过受验证的身份访问管理插件；缺失、伪造或过期身份不会被环境变量、默认主体或 cookie 自动替代，也不会触发 core 调用。

验收：F0-05。

## US-F0-04：后续实现人员可判断事实边界

作为后续阶段的实现人员，我能从 inventory 和测试知道哪些遗留文件只是研究资产，哪些生产路径已被隔离，因此不会错误复用旧 adapter 或控制面。

验收：F0-07。

## 边界

- 不把“源文件仍存在”称为“功能已启用”。
- 不把单元测试绿色称为 D0、G0、X0 或 F1 已通过。
- 不用隐藏 feature flag、进程内 Map 或开发环境约定替代路由、选择和身份边界的实际不可达性。
