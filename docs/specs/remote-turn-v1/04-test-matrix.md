## Validation order

1. Core pure schema/state/token/receipt tests, including `test/remote-turn-state-machine.test.ts` — a table-driven full transition matrix covering every legal transition in Round 2 and every illegal (state x event) pair.
2. Postgres transaction, concurrency, restart, and cross-instance (same-database two-pool) tests.
3. Fake runtime and fake attestor contract tests with adversarial messages, per the field-level schemas in 05-protocol-schema.md.
4. Private-layer image/attestor/egress/termination tests.
5. One-scope real canary and rollback drill.
6. Targeted typecheck/lint and an independent fresh-context security/code review.

Steps 1, 2, and 6 run continuously and in parallel with the others; step 6 is not deferred to the end. All new Postgres test files are registered in `npm run test:pg` with coordinated DROP lists against the shared test database.

No test is waived because a broader existing suite is green. No canary starts while any RTH-01 through RTH-13 criterion lacks its negative test; RTH-14's drills are the canary itself, so a separate rollback-drill rehearsal is the required pre-canary evidence.
