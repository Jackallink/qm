# Round 1 — 终局用户故事与验收边界

## 用户角色

| 角色 | 终局需要 | 不具备的权力 |
| --- | --- | --- |
| 最终用户 | 在已授权 scope 中发起、查看、暂停、取消或交接自己的任务 | 选择任意 runtime、模型、权限、网络或外部系统连接 |
| 审批人 | 对高风险动作看到可理解的影响、证据和替代方案后批准或拒绝 | 以审批绕过身份、预算、隔离或能力限制 |
| 发布者 | 发布已审核、版本化的 Agent 定义/Release | 直接使未认证的定义成为在线运行时 |
| 运营人员 | 观察真实状态、成本、风险和告警，执行可证明的停用/撤权/回滚 | 通过页面或 header 获得未授权控制权 |
| 外部治理权威 | 授权身份、Skill/能力状态和高风险动作，并接收审计 | 被平台绕过而直接访问受管业务系统 |
| Adapter/设备运营方 | 为某个运行时或设备形态提供认证、隔离、策略、升级与停止证明 | 代表核心策略或读取其他 scope 的数据 |
| 交付与合规负责人 | 将每项批准需求、目标环境和量化目标映射到可执行验收 | 用通用路线图替代目标环境或合同证据 |
| 业务验收方 | 以私有覆盖表指定的端到端场景验证用户价值和可运营性 | 把演示、API 返回或基准数字当作验收证据 |

## 终局故事

### US-00：可证明的交付前提

作为交付与合规负责人，我可以逐项确认批准需求、运行环境、外部依赖、责任方、验收与回滚证据；若目标持久化、部署、网络、许可或合规要求不可满足，系统在任何远程执行启用前记录阻塞或已批准差异。

覆盖阶段：F0、D0-L、D0-T。

### US-01：受治理的任务入口

作为最终用户，我只能经已授权入口以已验证身份提交任务；系统从服务器端确定我的 scope、权限和可用能力，每次受保护的能力调用都取得外部治理授权并回传统一 trace、错误和结果；拒绝时说明可理解原因而不泄露其他 scope 的存在。

覆盖阶段：G0、F1、C2、T1、O1。

### US-02：安全执行与可证明停止

作为最终用户，我只收到经过验证的结果；若我取消任务或系统发生超时，平台能证明运行时已经停止、其相关权限/令牌已撤销，或明确报告仍在处置而非伪造成功。

覆盖阶段：F1、C2、A1、T1、C3、O1。

### US-03：受控外部动作

作为最终用户，我可以在授权边界内使用 Skill、工具、文件、文档和记忆能力；每次外部动作都受到 capability、风险策略和必要审批控制，并可追溯其输入、输出、产物和补偿/撤销结果。输入输出、敏感数据、传输、存储和异常外发都受独立策略约束。

覆盖阶段：M1、A1、T1、O1。

### US-03a：受策略约束的模型与记忆

作为最终用户，我可以在服务端策略选定的模型和上下文中持续工作；系统按照用户、Agent、场景和权限隔离模型路由、上下文、长期记忆和工作区，并可说明其召回、更新、过期、删除、计量和审计结果。

覆盖阶段：C2、M1、A1、O1。

### US-04：可恢复的任务与人工接管

作为最终用户或审批人，我可以查看任务目标、计划、状态、失败节点和确认记录；长任务可按明确语义暂停、恢复、重试、取消或交由人工处理，已产生副作用的动作不会因重启被悄悄重复。

覆盖阶段：T1、C3、O1。

### US-05：受控的 Agent 发布与协同

作为发布者，我可以发布受审核、版本化、范围受限的 Agent 定义；平台只让已通过相应执行证明的 Release 运行。若外部治理授权公开级组合定义，用户只能组合已授权公开能力，且不得通过组合取得原子调用或内部级以上权限；协同、消息和定时任务在持久授权、幂等、预算与停止语义之上工作。

覆盖阶段：C1、A1、C3、X1。

### US-06：真实的运营与应急处置

作为运营人员，我可以按授权查看可验证的任务、审计、成本和风险信息，并对一个 scope、Release、能力或设备执行停用、撤权、回滚和恢复；返回结果逐目标反映实际执行状态。

覆盖阶段：O1、X1、B1。

### US-07：可认证的多运行时交付

作为 Adapter/设备运营方，我可以为 F1 参考运行时之外的一种云端、设备端或外部 Agent 运行形态完成独立认证。该运行形态不能绕过统一入口、治理授权、最小权限、隔离、egress、审计或撤权链路。

覆盖阶段：X1、B1。

### US-08：业务价值验收

作为业务验收方，我可以在私有需求覆盖表指定的端到端场景中验证：入口、授权、任务、能力、结果、审计、人工接管和回滚均按约定运行；合同指定的文档/文件处理范围、必达运行形态和量化指标均有可复验证据，而非由任意演示场景替代。

覆盖阶段：B1。

## 非故事与边界

- 不把 Skill 市场或 Skill 生命周期管理作为本平台功能；平台消费外部权威的已授权版本。
- 公开级组合定义是否由平台或外部治理权威实现，必须在私有需求覆盖表中指明 owner、版本、授权边界、审计和异常停用契约；它不能成为创建、审核、发布或市场运营的替代说法。
- 不允许 Agent、用户、浏览器或环境变量自行提高权限、选择任意网络出口、注入任意 CLI 参数，或直接访问受管外部系统。
- 不因引入某个 runtime、页面、数据库表、队列或 dashboard 而自动获得 Agent 平台能力。
- 不在缺少 durable state、负向测试、真实停止/回滚证据的前提下启用常驻 Agent、调度、协同或写操作。

## Round-1 批准条件

终局故事只在以下条件都成立时批准：业务需求覆盖表把每个故事映射到外部需求、owner 和验收人；每个故事至少对应一个阶段 Exit Gate；未归属的外部依赖和不在本包范围的能力已显式标出。
