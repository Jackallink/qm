# 业务需求覆盖协议

## 用途与归属

这是路线图的交付协议，不是业务需求正文。业务需求正文、编号、外部系统名称、合同数值、验收联系人和部署证据属于私有部署项目；上游 QM 只保留此通用字段和阶段约束。

私有部署项目必须建立一张逐项覆盖表。每个已编号的业务需求占一行；不得用“平台能力已覆盖”替代某一条具体需求，也不得把多个相互独立的红线、设备类型、场景或量化指标压缩为一行。该表必须在 D0-T 形成并在后续阶段持续更新；本文件只提供无组织信息的结构，不能证明任何具体需求已经覆盖。

## 每项必填字段

| 字段 | 要求 |
| --- | --- |
| 需求 ID 与来源版本 | 可定位到批准的业务/合同需求原文；变更后保留版本关系 |
| 范围与优先级 | `must`、`pilot`、`later`、`out-of-package` 或已批准差异；`must` 条目不得被试点替代 |
| 需求类型 | 功能、红线、集成、运行环境、合规、可用性、量化指标或业务场景 |
| 适用范围 | 组织、scope、用户角色、运行时/设备、数据分类和部署边界 |
| 路线图归属 | F0、D0-L、D0-T、G0、X0、F1、C1、C2、M1、A1、T1、C3、O1、X1 或 B1；跨阶段需求列出所有依赖 |
| 核心与部署层 owner | 指明是 vendor-neutral core、私有部署层、外部治理权威或业务系统责任方 |
| 规格与 AC | 链接到唯一 feature spec、验收条件和正向/负向/恢复测试 |
| 指标口径 | 对量化要求原样保留目标值；定义分母、窗口、排除条件、数据来源、告警和验收方法。基线不改变目标值 |
| 运行证据 | 链接到 canary、演练、审计 trace、监控数据、运行手册和回滚记录 |
| 验收人和状态 | 指明业务、运营和安全验收人；状态只能为 planned、in-progress、blocked、verified 或 accepted |
| 依赖、风险与回滚 | 外部依赖 owner、依赖故障策略、失败影响、禁用条件、恢复动作和证据保全位置 |
| 差异或豁免 | 无差异时明确为 none；否则链接到批准人、有效范围、期限、补偿控制和到期处置 |

## 最小表格形状

私有部署项目可使用任何可审计的系统保存覆盖表，但每项至少应能导出为下列形状：

| 需求 ID | 来源版本 | 范围/优先级 | 阶段 | owner | 规格/AC | 证据 | 验收人 | 状态 | 差异/豁免 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `REQ-...` | `...` | `must` | `D0-L/D0-T/F1/...` | `core/layer/external` | `path or ID` | `test/drill/UAT` | `role` | `planned` | `none or approval` |

## 不可合并的覆盖类别

下列类别必须分别可追踪，即使它们最终由同一功能实现：

1. 指定入口、身份授权、外部治理授权和审计回传。
2. 运行时兼容性红线、每个指定云端/设备端/外部运行形态及其注册、完整性、升级、停止和失联处置。
3. 任务、会话、模型路由/密钥/QoS/计量/效果评估、上下文/记忆/工作区隔离、预算、审批、取消、恢复和人工接管。
4. 已授权 Skill 的同步、验证、加载、执行、日志、异常停用，以及公开级组合定义与对外部生命周期系统的边界。
5. 工具、文件、指定文档处理范围、产物、外部业务动作、输入输出与数据安全、权限、密钥、隔离、egress 和结果校验。
6. Agent 定义/发布、版本、策略、协同、消息、调度、常驻执行和故障恢复。
7. 运营控制、逐目标应急动作、trace/实时通知/运营分析、审计读取、留存/导出/删除、备份恢复、灰度/升级兼容、可用性和合规部署要求。
8. 目标数据库、存储/消息依赖、部署编排、硬件/架构、操作系统、网络、加密、时间同步、许可和高可用要求。
9. 每个指定业务场景、用户验收、端到端 trace、量化指标定义、观测窗口和签核。

每个合同指定的运行时、adapter 或设备 profile 均为独立条目。D0-T 必须把首个 F1 参考 profile 映射至 X0，并把其余必达 profile 映射至各自的 X1 验收；不得用任意一个通过认证的 adapter 替代另一个必达 profile。

## 终局判定

只有覆盖表中每一个 `must` 项均为 `accepted`，并且每行都能追溯到已完成阶段、可复验证据与可执行的回滚/运维材料时，才可声明终局目标达成。任何 `must` 项为 `planned`、`in-progress`、`blocked`，或仅凭设计/API 演示的条目，都意味着终局尚未达成。`pilot`、`later` 和 `out-of-package` 仅在批准范围明确允许时可不阻塞该声明，并必须保留其外部 owner 或排除依据。
